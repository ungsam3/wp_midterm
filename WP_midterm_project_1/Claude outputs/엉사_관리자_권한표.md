# 엉뚱한 사람들 웹페이지 — 관리자 권한표 (최종)

## 1. 계정

| 이름(표시) | role | 학번 | 비밀번호 | 생성 방식 |
|---|---|---|---|---|
| 회장 | `president` | `0` | `ghlwkd0!` | 코드에 미리 저장 |
| 부회장 | `vice` | `1` | `qnghlwkd1!` | 코드에 미리 저장 |
| 동방장 | `dbmanager` | `2` | `ehdqkdwkd2!` | 코드에 미리 저장 |
| (가입한 이름) | `member` | 가입 시 입력 | 가입 시 입력 | 회원가입 |

- `auth.js`의 회원 객체: `{ name, studentId, email, password, role }`
- 로그인할 때 `role`과 이름을 localStorage에 저장하고, 페이지마다 `role`을 보고 관리 기능을 보여줌
- 관리자 학번(0, 1, 2)은 학번 중복 검사 때문에 회원가입으로 사용할 수 없음

## 3. 페이지별 상세

### 교육자료
- 대기 목록은 따로 만들지 않음
- 항목 배치: `작성자 | [분류태그] 제목 [인증배지] (작성일·조회수) ……… [승인] [승인취소]`
  - 인증 배지: 제목 바로 옆
  - 승인 → 승인취소 순서로 항목 오른쪽 맨 끝에 배치, 상태와 관계없이 둘 다 항상 보임
- 승인 클릭 → 인증 배지 보임 / 승인취소 클릭 → 인증 배지 안 보임
- 항목 클릭 처리(조회수 +1, 내용 펼치기)에서 두 버튼 클릭은 제외
- 샘플 자료 초기 상태
  - 미승인: `음성인식 기반 인형 뽑기 프로젝트`, `변박사 제작 후기`
  - 나머지 22개는 승인 상태
- 새로 작성한 글은 관리자 글을 포함해 모두 미승인으로 시작
- 글과 승인 상태는 모두 localStorage에 저장

### 비품
- 기존 비품 모달에는 편집 기능을 넣지 않음
- 추가 비품 버튼은 팀원이 만들면 구현하고, JSON 형태로 localStorage에 저장
- 비품 데이터 경로(`equipment.json` ↔ `10_yes3_equipment.json`)는 팀원과 논의 후 결정

### 청소담당
- 조 배정표: 이름 칸만 편집 가능 (일정표에는 영향 없음), localStorage에 저장
- 체크 상태: localStorage에 저장 (새로고침해도 유지)
- 체크 초기화: 누르면 저장된 체크 상태도 같이 삭제
- 청소 일정표: 4개월씩 보여주는 지금 형태 유지
  - 2학기: 2026년 9~12월 (지금 버전, 1조 시작 2026-08-31)
  - 1학기: 2027년 4~7월 (1조 시작 2027-04-05 월요일), 같은 형태·스타일
  - 선택한 학기는 localStorage에 저장하고 모든 회원 화면에 적용

### 응원 댓글
- 초기 댓글은 그냥 기존 코드에 있는 거 보이게 하고, 추가·삭제 결과는 localStorage에 저장
- 하트(좋아요)는 현재 그대로 둠 (저장하지 않음)

## 4. 데이터 저장 정리

| 데이터 | 저장 방식 |
|---|---|
| 회원 목록 (role 포함) | localStorage `users` |
| 로그인 정보 (이름, role, 로그인 상태) | localStorage |
| 교육자료 목록 + 승인 상태 | localStorage |
| 추가 비품 (구현 시) | localStorage (JSON 형태) |
| 청소 조 배정표 이름 | localStorage |
| 청소 체크 상태 | localStorage |
| 청소 일정표 학기 선택 | localStorage |
| 응원 댓글 | 초기값은 JSON 파일, 추가·삭제는 localStorage |

## 5. 참고

- localStorage는 브라우저마다 따로 저장되므로, 관리자가 바꾼 내용은 같은 브라우저에서만 반영됨 (발표 시연에서는 문제없음)
- 관리자 비밀번호가 `auth.js`에 평문으로 들어가므로, 공개 레포라면 누구나 볼 수 있음
- 샘플 데이터를 localStorage에 한 번 저장한 뒤에는 코드에서 샘플을 고쳐도 반영되지 않음 → 테스트할 때 개발자도구에서 해당 키를 삭제해야 함
